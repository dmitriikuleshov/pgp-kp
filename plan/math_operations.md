# Сложные операции математического ядра

Ниже разобраны содержательные операции из `src/math.cuh`, кроме обычных
сложения, вычитания, умножения и деления.

## Скалярное произведение — `dot`

```cpp
double dot(const Vec3 &left, const Vec3 &right) {
    return left.x * right.x
         + left.y * right.y
         + left.z * right.z;
}
```

Математически:

$$
a \cdot b = a_x b_x + a_y b_y + a_z b_z.
$$

Результат — одно число.

Например:

```text
a = (1, 2, 3)
b = (4, 5, 6)

dot(a, b) = 1 * 4 + 2 * 5 + 3 * 6 = 32
```

Геометрический смысл:

$$
a \cdot b = |a| |b| \cos \alpha,
$$

где $\alpha$ — угол между векторами.

Из этого следуют важные случаи:

- `dot(a, b) > 0` — векторы смотрят примерно в одну сторону;
- `dot(a, b) < 0` — векторы смотрят примерно в противоположные стороны;
- `dot(a, b) == 0` — векторы перпендикулярны.

Например:

```text
a = (1, 0, 0)
b = (0, 1, 0)

dot(a, b) = 0
```

В ray tracing скалярное произведение понадобится для освещения:

```cpp
brightness = dot(normal, direction_to_light);
```

Если источник расположен перед поверхностью, яркость положительна. Если он
расположен позади поверхности, яркость отрицательна, поэтому ее заменяют нулем.

## Векторное произведение — `cross`

```cpp
Vec3 cross(const Vec3 &left, const Vec3 &right) {
    return Vec3(
        left.y * right.z - left.z * right.y,
        left.z * right.x - left.x * right.z,
        left.x * right.y - left.y * right.x
    );
}
```

Математически:

$$
a \times b =
\begin{pmatrix}
a_y b_z - a_z b_y \\
a_z b_x - a_x b_z \\
a_x b_y - a_y b_x
\end{pmatrix}.
$$

Результат — новый вектор, перпендикулярный обоим исходным.

Пример:

```text
a = (1, 0, 0)
b = (0, 1, 0)

cross(a, b) = (0, 0, 1)
```

То есть произведение оси X на ось Y дает направление оси Z.

Порядок имеет значение:

```text
cross(a, b) =  (0, 0, 1)
cross(b, a) =  (0, 0, -1)
```

Иными словами:

$$
a \times b = -(b \times a).
$$

В проекте это потребуется для:

- вычисления нормали треугольника;
- построения осей камеры;
- определения ориентации поверхности.

Например, для треугольника с вершинами $A$, $B$, $C$:

```cpp
Vec3 edge1 = B - A;
Vec3 edge2 = C - A;
Vec3 normal = normalize(cross(edge1, edge2));
```

Порядок вершин определяет, наружу или внутрь будет направлена нормаль.

## Квадрат длины — `length_squared`

```cpp
double length_squared(const Vec3 &vector) {
    return dot(vector, vector);
}
```

Для вектора $v = (x, y, z)$ получаем:

$$
|v|^2 = x^2 + y^2 + z^2.
$$

Например:

```text
v = (2, 3, 6)

length_squared(v) = 4 + 9 + 36 = 49
```

Эта функция существует отдельно, потому что иногда нужно только сравнить
расстояния.

Вместо:

```cpp
if (length(a) < length(b))
```

можно написать:

```cpp
if (length_squared(a) < length_squared(b))
```

Результат сравнения будет тем же, но вычислять квадратный корень не потребуется.
На GPU это быстрее.

## Длина — `length`

```cpp
double length(const Vec3 &vector) {
    return sqrt(length_squared(vector));
}
```

Математически:

$$
|v| = \sqrt{x^2 + y^2 + z^2}.
$$

Например:

```text
v = (2, 3, 6)

length(v) = sqrt(49) = 7
```

Если две точки заданы как `a` и `b`, то расстояние между ними вычисляется так:

```cpp
double distance = length(b - a);
```

Сначала `b - a` дает направление от `a` к `b`, а затем `length` вычисляет длину
этого направления.

## Нормализация — `normalize`

```cpp
Vec3 normalize(const Vec3 &vector) {
    const double vector_length = length(vector);

    if (vector_length == 0.0) {
        return Vec3();
    }

    return vector / vector_length;
}
```

Нормализация сохраняет направление, но делает длину вектора равной единице:

$$
\hat v = \frac{v}{|v|}.
$$

Пример:

```text
v = (3, 0, 0)
length(v) = 3

normalize(v) = (1, 0, 0)
```

Другой пример:

```text
v = (3, 4, 0)
length(v) = 5

normalize(v) = (0.6, 0.8, 0)
```

Проверка:

$$
\sqrt{0.6^2 + 0.8^2} = 1.
$$

Единичные векторы необходимы, чтобы вычисления зависели только от направления,
а не от случайной длины вектора.

Нормализованными должны быть:

- направление луча;
- нормаль поверхности;
- направление к источнику света;
- оси камеры.

Нулевой вектор нормализовать невозможно, поскольку пришлось бы делить на ноль.
Поэтому функция возвращает `(0, 0, 0)`.

## Отражение — `reflect`

```cpp
Vec3 reflect(const Vec3 &incident, const Vec3 &normal) {
    return incident - 2.0 * dot(incident, normal) * normal;
}
```

Формула:

$$
r = d - 2(d \cdot n)n,
$$

где:

- $d$ — направление падающего луча;
- $n$ — нормаль поверхности;
- $r$ — отраженное направление.

Представим горизонтальную поверхность:

```text
normal = (0, 1, 0)
```

Луч летит вправо и вниз:

```text
incident = (1, -1, 0)
```

Скалярное произведение:

$$
d \cdot n = -1.
$$

Подставляем:

$$
r = (1, -1, 0) - 2(-1)(0, 1, 0),
$$

$$
r = (1, -1, 0) + (0, 2, 0) = (1, 1, 0).
$$

Получилось направление вправо и вверх:

```text
incident  = (1, -1, 0)
reflected = (1,  1, 0)
```

Фактически у направления меняется составляющая, перпендикулярная поверхности, а
параллельная составляющая остается прежней.

Формула предполагает, что `normal` имеет длину 1.

## Ограничение числа — `clamp`

```cpp
double clamp(double value, double minimum, double maximum)
```

Функция помещает значение внутрь заданного диапазона:

```text
clamp(-2.0, 0.0, 1.0) = 0.0
clamp( 0.4, 0.0, 1.0) = 0.4
clamp( 3.0, 0.0, 1.0) = 1.0
```

Логика:

```cpp
if (value < minimum)
    return minimum;

if (value > maximum)
    return maximum;

return value;
```

## Ограничение вектора

```cpp
Vec3 clamp(const Vec3 &vector, double minimum, double maximum)
```

Та же операция применяется отдельно к каждому компоненту:

```text
vector = (-1.0, 0.4, 2.0)

clamp(vector, 0.0, 1.0) = (0.0, 0.4, 1.0)
```

## Ограничение цвета — `clamp_color`

```cpp
Vec3 clamp_color(const Vec3 &color) {
    return clamp(color, 0.0, 1.0);
}
```

Внутри трассировщика цвет хранится нормированным:

```text
черный  = (0, 0, 0)
красный = (1, 0, 0)
белый   = (1, 1, 1)
```

После суммирования нескольких источников света может получиться:

```text
(1.3, 0.7, -0.1)
```

Перед преобразованием в байты цвет ограничивается:

```text
(1.0, 0.7, 0.0)
```

А затем переводится в диапазон `[0, 255]`:

```text
(255, 178, 0)
```

## Точка на луче — `Ray::at`

Луч задается началом и направлением:

```cpp
struct Ray {
    Vec3 origin;
    Vec3 direction;
};
```

Любая точка на луче определяется формулой:

$$
P(t) = O + tD.
$$

В коде:

```cpp
Vec3 at(double distance) const {
    return origin + direction * distance;
}
```

Например:

```text
origin    = (1, 2, 3)
direction = (0, 0, 1)
t         = 5
```

Тогда:

```text
P(5) = (1, 2, 3) + 5 * (0, 0, 1)
     = (1, 2, 8)
```

Когда будет найдено пересечение с объектом, алгоритм вернет значение `t`. Точка
пересечения получится так:

```cpp
Vec3 hit_point = ray.at(t);
```

Если направление нормализовано, значение `t` одновременно является расстоянием
от начала луча. Если направление не единичное, `t` остается параметром, но уже
не равно физическому расстоянию.
