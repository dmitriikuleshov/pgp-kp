# План выполнения курсового проекта

Этот каталог временный. Он используется для ведения плана и фиксации прогресса
во время разработки. После завершения проекта каталог `plan` можно удалить.

## Задание

Тема: обратная трассировка лучей (Ray Tracing) на GPU с использованием CUDA.

Вариант №3:

1. Тетраэдр.
2. Гексаэдр (куб).
3. Икосаэдр.

Итоговая программа должна поддерживать CPU- и GPU-рендеринг, текстурированный
пол, освещение, тени, отдельные ребра с источниками света, отражение,
прозрачность, рекурсивную трассировку, SSAA и покадровую анимацию.

## Порядок совместной работы

Каждый этап выполняется отдельно:

1. Разбираем необходимую теорию.
2. Определяем небольшой проверяемый результат.
3. Реализуем только текущий этап.
4. Собираем и запускаем программу.
5. Проверяем результат и граничные случаи.
6. Разбираем ключевые участки кода.
7. Отмечаем этап завершенным и переходим к следующему.

Новый этап не должен ломать уже работающие возможности. `report/report.typ` не
изменяется до этапа подготовки отчета.

## Статусы

- `[ ]` — не начато;
- `[~]` — выполняется;
- `[x]` — завершено и проверено.

## Этапы

### [x] 0. Каркас проекта

Создать структуру исходников, `Makefile` и исполняемый файл. Реализовать разбор
ключей `--cpu`, `--gpu`, `--default`. Запуск без аргументов должен соответствовать
`--gpu`.

Критерий готовности: проект собирается через `make`, все режимы запускаются и
корректно выбираются.

### [x] 1. Математическое ядро

Реализовать `Vec3`, основные векторные операции, нормализацию, `Ray`, отражение
направления и ограничение цвета. Математические функции должны работать и на
CPU, и на GPU с помощью `__host__ __device__`.

Критерий готовности: операции проверены на небольших численных тестах.

### [x] 2. Формат изображений

Реализовать запись бинарных изображений формата лабораторной №2:

```text
int32 width
int32 height
width * height пикселей RGBA
```

Добавить преобразование `.data` в PNG и сгенерировать тестовый градиент.

Критерий готовности: созданный программой `.data` корректно преобразуется и
просматривается как изображение.

### [x] 3. Входная конфигурация

Описать структуры камеры, тел, пола, источников света и параметров рендеринга.
Реализовать чтение полного входного формата. `--default` должен печатать
синтаксически корректную конфигурацию и завершаться без рендеринга.

Критерий готовности: конфигурация читается и может быть выведена обратно без
потери параметров.

### [x] 4. Камера и первичные лучи на CPU

Реализовать движение камеры в цилиндрических координатах, перевод в декартовы
координаты, базис камеры, горизонтальный FOV и луч через каждый пиксель.

Критерий готовности: CPU формирует изображение направлений лучей, которое
предсказуемо меняется при движении камеры.

### [x] 5. Пересечение луча с треугольником

Добавить структуры `Triangle`, `Material`, `Hit` и реализовать алгоритм
пересечения луча с треугольником, например Moller–Trumbore.

Критерий готовности: на CPU отображается один треугольник на черном фоне.

### [x] 6. Платоновы тела варианта №3

Последовательно построить тетраэдр, куб и икосаэдр. Вершины должны
масштабироваться по радиусу описанной сферы и переноситься в указанный центр.
Нормали граней должны быть направлены наружу.

Критерий готовности: CPU отображает правильные силуэты трех тел с плоскими
цветами.

### [x] 7. Простое освещение и тени

Добавить фоновую составляющую, диффузное освещение Ламберта, ослабление света с
расстоянием, несколько внешних источников и теневые лучи.

Критерий готовности: тела выглядят объемными и отбрасывают тени. Получена первая
законченная простая CPU-версия трассировщика.

### [x] 8. Первая CUDA-версия

Перенести на GPU генерацию первичных лучей, поиск пересечений и простое
освещение. Один CUDA-поток обрабатывает один пиксель.

Критерий готовности: CPU- и GPU-изображения одинаковой тестовой сцены совпадают
с учетом допустимой погрешности округления.

### [x] 9. Произвольный текстурированный пол

Разбить четырехугольный пол на два треугольника, вычислять UV через
барицентрические координаты, читать текстуру `.data` и учитывать оттенок пола.
Реализовать одинаковое поведение на CPU и GPU.

Критерий готовности: текстура корректно отображается на произвольно заданном
четырехугольном полу.

### [x] 10. Отдельные ребра тел

Сформировать списки уникальных ребер и добавить им отдельную видимую геометрию,
например конечные цилиндры или тонкие трубки.

Критерий готовности: у всех трех многогранников видны непрерывные отдельные
ребра.

### [x] 11. Источники света на ребрах

Равномерно расположить заданное количество точечных источников на каждом ребре,
подключить их к освещению и при необходимости добавить небольшую видимую
светящуюся геометрию.

Критерий готовности: источники видны на ребрах и освещают остальные элементы
сцены.

### [x] 12. Однократное отражение

Реализовать отраженный луч и смещение его начала на `epsilon`, чтобы исключить
самопересечение.

Критерий готовности: объекты отражаются в полу и зеркальных гранях при глубине,
равной единице.

### [x] 13. Прозрачность

Реализовать проходящий луч без преломления, так как показатель преломления во
входных данных отсутствует. Смешивать локальный, отраженный и проходящий цвета с
учетом коэффициентов материала.

Критерий готовности: через грани тел видны пол и другие объекты, отсутствуют
зацикливания на одной поверхности.

### [x] 14. Полная рекурсивная трассировка

Сначала проверить рекурсивный алгоритм на CPU, затем реализовать явный стек
лучей для CUDA. Добавить максимальную глубину, прекращение ветвей с малым
вкладом, защиту от переполнения стека и подсчет лучей.

Критерий готовности: многократные отражения источников внутри прозрачных тел
создают эффект бесконечности в CPU- и GPU-режимах.

### [x] 15. SSAA

Для параметра `s` строить сетку из `s * s` подлучей внутри каждого пикселя и
усреднять их цвета. Проверить значения `s = 1`, `2` и `4` до запуска более
дорогих режимов.

Критерий готовности: контуры тел и ребер сглажены, а `s = 1` сохраняет прежний
результат.

### [x] 16. Полная анимация

Добавить цикл по кадрам, вычисление времени движения камеры, подстановку номера
кадра вместо `%d`, сохранение изображения и статистику:

```text
номер_кадра<TAB>время_мс<TAB>общее_число_лучей
```

Критерий готовности: программа создает последовательность кадров с плавным
облетом сцены.

### [x] 17. Систематическая проверка CPU и GPU

Подготовить небольшие сцены для проверки треугольников, отдельных тел, пола,
освещения, отражения, прозрачности и полной рекурсии. Сравнивать размеры,
пиксели, численные отклонения и количество лучей.

Критерий готовности: CPU используется как надежный эталон, а отличия GPU
объяснимы погрешностью вычислений.

### [ ] 18. Оптимизация

Ускорять только проверенную реализацию: убрать лишние вычисления и копирования,
подобрать размеры CUDA-блоков, использовать подходящие виды памяти, отсекать
слабые рекурсивные ветви и при необходимости добавить ускорение поиска
пересечений.

Критерий готовности: GPU дает заметное ускорение относительно CPU без изменения
изображения.

### [ ] 19. Финальная конфигурация и анимация

Подобрать красивые параметры тел, пола, света и камеры для `--default`.
Отрендерить финальные кадры, преобразовать их в обычные изображения и собрать
GIF или видео. Провести итоговый бенчмарк.

Критерий готовности: имеется законченная демонстрационная анимация и данные для
сравнения производительности.

### [ ] 20. Отчет

Описать постановку задачи, вариант, математику камеры и трассировки, устройство
CPU- и GPU-реализаций, тестирование, SSAA, оптимизации и результаты измерений.
Добавить изображения и выводы.

Критерий готовности: `report.typ` компилируется, отчет соответствует фактической
реализации и содержит результаты всех необходимых экспериментов.
